# The agentd names people can still see in LibraOS Next

The app is **LibraOS Next**. The engine it bundles is **LibraOS Core**, whose command is
`libraos-core` (`agentd` stays an alias); its repository is `libraos/libraos-core`. This page lists
what was renamed in the last pass and every `agentd` / `AgentD` name a person can still meet, why it
stays, and what renaming it later would take. Code identifiers (types, functions, files, the
`agentd/` directory) are not listed: no one sees them.

## Renamed in this pass

Earlier passes renamed the web, mobile and desktop translation catalogs and the user docs
(`agentd/patches/1038-libraos-rename-i18n.md`, `1038-libraos-user-docs.md`). This pass renamed what
they left:

- **Server, CLI and packages.** Every "AgentD Next" in a string under `apps/server/src`,
  `apps/desktop/src` and `packages/*/src` became "LibraOS Next": CLI help, usage and printed hints,
  errors shown in the app (database, ownership, service, relay, preview browser, providers, source
  control), the systemd and Windows service descriptions, the Codex sign-in pages, the MCP OAuth
  resource name, the GitHub sign-in app name, the work-log tool rows, `t3.json` schema descriptions,
  the triage playbook (`.github/triage/PLAYBOOK.md` and its byte-identical copy) and the text agents
  read about the app (pull request watch updates, restart notes). Recorded test fixtures follow.
- **Engine errors.** Messages that said "AgentD" or "agentd" for the engine (agentd not found, did
  not answer, Cloud Workers failures, Repair, the gateway's model key) say "LibraOS Core", and the
  commands they suggest are `libraos-core install` and `libraos-core upgrade`.
- **Passkey chooser.** The desktop's passkey dialog has its own title; without one, Windows titles it
  with Electron's app name (below).
