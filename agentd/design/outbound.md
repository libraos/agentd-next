# Outbound endpoints

What the server and clients in this build still reach over the network, and what starts each request. With no configuration the server sends nothing to PostHog or `ingest.t3.codes`, and fetches nothing from `raw.githubusercontent.com/pingdotgg` (see `agentd/patches/3-no-upstream-telemetry.md`).

## Off unless configured

| Endpoint                                                                                                                   | Turned on by                                                                                                                                       | Code                                                                  |
| -------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| Product analytics (PostHog batch API)                                                                                      | Both `T3CODE_POSTHOG_KEY` and `T3CODE_POSTHOG_HOST`. `T3CODE_TELEMETRY_ENABLED=false` or the managed `telemetry` policy still turns it off         | `apps/server/src/telemetry/AnalyticsService.ts`                       |
| Remote model manifest                                                                                                      | `T3CODE_MODEL_MANIFEST_URL`; also needs the "provider update checks" setting on. Otherwise only the bundled `provider/model-manifest.json` is used | `apps/server/src/provider/ModelManifest.ts`                           |
| Triage source repository (`git ls-remote`, shallow clone) and the agent's playbook steps that fetch, search or file issues | `T3CODE_TRIAGE_REPOSITORY` (a repository URL). Without it triage runs locally and the context file says "Repo: none configured"                    | `apps/server/src/triage/`                                             |
| Relay client tracing (OTLP)                                                                                                | `T3CODE_RELAY_CLIENT_OTLP_TRACES_URL`, `_DATASET` and `_TOKEN`, at build time or run time, all three, and relay tracing enabled                    | `apps/server/src/cloud/publicConfig.ts`                               |
| T3 Connect relay, Clerk sign-in                                                                                            | `T3CODE_RELAY_URL`, `T3CODE_CLERK_PUBLISHABLE_KEY` at build or run time; empty by default                                                          | `apps/server/src/cloud/publicConfig.ts`, `apps/server/vite.config.ts` |

## On a user action or a configured provider

| Endpoint                                                                                                                     | Trigger                                                                                                                                                                                                                                                                                                                                 | Code                                                                                                                                                               |
| ---------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Provider CLIs and their own APIs (Anthropic, OpenAI/ChatGPT, Cursor, xAI, Google, OpenCode, ...)                             | Starting a turn or a session with that provider; the CLI talks to its vendor itself. At startup the server also probes installed provider CLIs (version, sign-in, models), which reach their vendors: an unconfigured run on a host with Codex and Claude Code installed looked up `chatgpt.com`, `claude.ai` and `releases.openai.com` | `apps/server/src/orchestration-v2/Adapters/`, `packages/provider-*`                                                                                                |
| Provider usage and rate limits (`api.anthropic.com/api/oauth/usage`, `chatgpt.com/backend-api/wham`, ...)                    | Opening usage views for a signed-in provider                                                                                                                                                                                                                                                                                            | `apps/server/src/usage/cliproxyApi.ts`, `apps/server/src/provider/claudeResetCredits.ts`                                                                           |
| Provider install and version checks (`registry.npmjs.org`, `github.com/openai/codex/releases`, the Antigravity CLI manifest) | Installing or updating a provider, and periodic checks while "provider update checks" is on                                                                                                                                                                                                                                             | `apps/server/src/provider/CodexInstallation.ts`, `apps/server/src/provider/AntigravityInstallation.ts`, `packages/provider-core/src/server/maintenanceResolver.ts` |
| ACP Registry (`cdn.agentclientprotocol.com`)                                                                                 | Browsing or installing an ACP Registry agent                                                                                                                                                                                                                                                                                            | `packages/contracts/src/acpRegistry.ts`, `packages/provider-acp-registry`                                                                                          |
| GitHub, GitLab, Bitbucket, Azure DevOps, Forgejo APIs and git remotes                                                        | Source control actions on a project: sign-in, pull requests, fetch/push, status refresh of a repository with a remote                                                                                                                                                                                                                   | `apps/server/src/sourceControl/`, `packages/source-control-*`, `apps/server/src/vcs/`                                                                              |
| Speech model downloads (`huggingface.co`)                                                                                    | The user downloads a local speech model                                                                                                                                                                                                                                                                                                 | `apps/server/src/speech/SpeechModelStore.ts`                                                                                                                       |
| Cloud speech (`api.openai.com`, `api.x.ai`, `openrouter.ai`)                                                                 | The user picks a cloud transcription provider and dictates                                                                                                                                                                                                                                                                              | `apps/server/src/speech/CloudSpeech.ts`                                                                                                                            |
| Model token prices (LiteLLM file on `raw.githubusercontent.com/BerriAI`, `api.github.com`)                                   | Usage cost views                                                                                                                                                                                                                                                                                                                        | `apps/server/src/usage/UsageService.ts`                                                                                                                            |
| npm release metadata (`registry.npmjs.org/t3`) and self-update                                                               | Checking for or applying a server update                                                                                                                                                                                                                                                                                                | `apps/server/src/cloud/npmRelease.ts`, `apps/server/src/cloud/selfUpdate.ts` (owned by another task)                                                               |
| Expo (`api.expo.dev`)                                                                                                        | Mobile device builds from the Device panel                                                                                                                                                                                                                                                                                              | `apps/server/src/device/`                                                                                                                                          |
| MCP servers and their OAuth                                                                                                  | MCP servers the user configured                                                                                                                                                                                                                                                                                                         | `apps/server/src/auth/McpOAuth.ts`                                                                                                                                 |
| Preview browser pages                                                                                                        | URLs the user or agent opens in the preview browser                                                                                                                                                                                                                                                                                     | `apps/server/src/preview/`                                                                                                                                         |

## Not covered here

Desktop release checks (`apps/desktop/`, `apps/web/src/components/desktopUpdate.logic.ts`) and links in branding (`apps/web/src/branding.ts`) belong to other tasks. Plain links the user clicks (docs, issue pages) are not requests the app makes on its own.

## How this was checked

An unconfigured server (`--base-dir` scratch, no `T3CODE_*` variables) ran for 45 seconds under `strace -f -e trace=connect,sendto`: no DNS lookup of PostHog, `ingest.t3.codes` or `raw.githubusercontent.com`. The same run with `T3CODE_MODEL_MANIFEST_URL` set did look up `raw.githubusercontent.com`.
